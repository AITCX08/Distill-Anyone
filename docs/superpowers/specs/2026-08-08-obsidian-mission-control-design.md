# 黑曜石作战台设计

## 目标

将 Distill-Anyone Dashboard 重构为一个中文、本地优先的内容蒸馏作战台。用户应能在一个视图中明确知道当前任务、当前作品、所处阶段、可信的进度指标、剩余时间和实时日志。

本次重构只调整 Dashboard 的信息架构、视觉系统与前端交互，不改变现有 FastAPI、SSE、任务状态机或蒸馏执行流程。

## 设计原则

- 作战台优先于卡片展示。实时执行信息必须比装饰更突出。
- 一个页面只服务一个工作目标。创建、监控、平台登录、历史和产物不再纵向堆叠。
- 数字、速率、ETA 和日志用等宽字体；中文业务信息保持易读。
- 深石墨背景、蓝灰表面、低饱和青绿是唯一常规强调色。红色与黄色只表示失败或告警。
- 动效只服务真实状态变化，例如进度更新、日志进入和详情展开；尊重 `prefers-reduced-motion`。
- 保留现有 Fluent UI 组件与无障碍行为，不混用新的设计系统。

## 信息架构

左侧导航维持既有锚点和可访问名称，但改为可收起的窄导航栏。桌面默认显示图标与文字，窄屏折叠为水平导航。

| 工作区 | 目的 | 首要信息 |
| --- | --- | --- |
| 作战台 | 监控当前运行任务 | 进度、当前作品、ETA、日志、控制动作 |
| 新建任务 | 预检并创建任务 | 来源、输出、可处理数量、预检结果 |
| 平台与登录 | 管理平台凭据状态 | 是否登录、支持类型、发起扫码 |
| 任务历史 | 回溯和重试任务 | 任务状态、失败项、项目操作 |
| 产物库 | 查看安全产物 | Markdown 预览、复制、打开所在文件夹 |

页面在同一壳层中切换工作区。现有的 `#mission`、`#create`、`#platforms`、`#history`、`#artifacts` 锚点保留，避免破坏已有链接和测试契约。

## 作战台布局

桌面端使用三层结构：

1. 顶部状态条：本地引擎状态、任务名、完成数、全局 ETA 和任务控制操作。
2. 概览区：整体进度、当前阶段、实时吞吐与剩余时间四项真实指标。没有服务端数据的指标显示“未知”，不得推测数值。
3. 主工作区：左侧为作品执行队列，右侧为固定高度的实时日志终端；底部提供失败项、可重试项和产物的详情抽屉。

系列任务在概览区下方显示一条按集数排序的作品轨道。轨道只表达已完成、执行中、等待、失败和暂停等语义状态。点击某一集会选中相应执行行并在详情抽屉展开。

作品执行队列使用紧凑行，不使用连续的大卡片。每行包括：

- 集数、标题和来源标识。
- 中文阶段标签。
- 与阶段匹配的指标：下载阶段显示已传输、总大小、速率与下载 ETA；转写阶段显示音频进度与实时系数；其他阶段显示明确的“正在估算”或服务端提供的阶段进度。
- 一条仅在服务端提供可信数值时显示的进度条。

实时日志采用只读等宽面板，保留服务端原始日志文本以便排错。新日志自动跟随到底部，但用户手动向上滚动后不强制跳回。

## 新建任务与登录

新建任务使用左右两栏：左侧为创作者链接、平台和输出选项，右侧为预检结果。创建按钮只有在预检指纹有效时可用。预检信息要明确显示可处理数、跳过数、未支持数和登录要求。

平台与登录页面采用平台状态列表。后续扫码能力以原地模态层承载，模态层展示二维码或浏览器会话状态，不显示 Cookie、令牌或凭据。当前外部浏览器登录接口在后端能力就绪前保持兼容，并在 UI 中明确说明当前登录方式。

## 组件边界

| 组件 | 职责 | 输入 |
| --- | --- | --- |
| `DashboardShell` | 导航、顶栏和工作区切换 | 当前路由、引擎状态 |
| `MissionHeader` | 当前任务总览和控制 | `ProgressSnapshot`、`MissionJob` |
| `SeriesRail` | 系列中每集的语义状态 | 作品快照列表、选中项 |
| `ExecutionQueue` | 紧凑执行行与选择状态 | 活动项目、选中项 |
| `ExecutionRow` | 单作品阶段指标 | 单个 `ActiveItem` |
| `LiveTracePanel` | 实时日志与自动跟随策略 | 日志条目 |
| `TaskDetailDrawer` | 失败、重试和产物详情 | 任务和项目数据 |
| `CreateMissionWorkspace` | 预检和创建流程 | 现有预检 API |
| `PlatformLoginWorkspace` | 平台状态和登录入口 | 平台 API |

现有 API schema 和 SSE 事件保持不变。展示层只通过既有 hooks 和 API client 获取数据，避免把请求逻辑放入纯展示组件。

## 状态与异常处理

- SSE 断开时保留最后一份已确认快照，并在顶栏显示“连接中断”。不把旧数据伪装成实时数据。
- API 未确认操作时显示中文行内错误，并保持服务器返回的状态为准。
- 没有活动任务时显示引导状态，引导用户前往“新建任务”。
- 没有日志、没有产物、无平台适配器时分别使用对应的空状态，不显示空白面板。
- 所有 ETA、大小和速率均以服务端实际值为准；未知值必须显示为“未知”。

## 响应式与无障碍

- 宽度低于 768px 时，主工作区按“概览、执行队列、日志”顺序单列排列。
- 顶栏操作折叠为可访问的操作菜单；导航变成可横向滚动的标签栏。
- 键盘可进入导航、任务行、详情抽屉、控制按钮和登录入口。
- 所有状态仅使用颜色以外的文字和图标表达。
- 输入框、选择器、进度与错误文案在深色主题下满足 WCAG AA 对比度。

## 验收标准

1. 桌面端首次进入作战台，无需滚动即可看到任务状态、总体进度、当前作品和实时日志。
2. 下载、转写和无已知总量三类活动项目展示不同且真实的指标，不出现伪造的 `0.0 KB`。
3. 所有静态用户界面文案、已知平台名和已知状态均为中文；原始标题与原始服务端日志保持原文。
4. 现有任务预检、创建、暂停、恢复、重试、历史和产物 API 行为不回归。
5. 窄屏可完成查看任务、创建任务和发起平台登录。
6. 单元测试覆盖阶段指标切换、空状态、断线状态、作品选择和键盘访问；现有测试继续通过。
7. 前端生产构建、静态资源发布校验与 Dashboard 根路由健康检查均通过。

## 非目标

- 本次不修改平台爬取器、LLM 管线或系列任务状态文件格式。
- 本次不将 Cookie、二维码原始数据或任何凭据传到前端。
- 本次不引入第二套组件库或大型动画依赖。
