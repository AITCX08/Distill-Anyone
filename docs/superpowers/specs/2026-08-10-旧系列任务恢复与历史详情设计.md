# 旧系列任务恢复与历史详情设计

## 目标

让已导入的 B 站系列任务在执行器退出后准确呈现为可恢复的阻塞状态；恢复后以现有本地登录凭据重新启动受控执行器。同时让任务历史显示每集标题，并通过受本地会话保护的详情入口展示交付位置与打开文件夹操作。

## 已确认的根因

- `SeriesTaskBridge` 将旧系列的每集标题仅放入 SSE 快照，`GET /api/v1/jobs/{job_id}/items` 没有该字段，历史页只能显示 `source_id`。
- 旧系列的 `JobState.request` 未保存 `output_directory`，因此现有私有交付详情接口无法返回保存位置。
- 系列执行器已退出时，`runtime.json` 仍可能残留 `status: "running"`。`SeriesController.resume()` 因此直接返回而不重启执行器。
- 当前任务第 7 集的最后一次失败是知识提取未产出可用结果；第 8 集尚未执行。有效 B 站凭据已存在，但没有存活的系列执行器。

## 设计

### 1. 旧系列桥接数据

桥接器将每集的 `title`、`part_number` 与系列的交付目录写入受控的 `JobState` 投影。交付目录由旧系列状态中的 `output` 推导其父目录；若尚未生成汇总产物，则由受控运行器登记的显式输出目录提供。目录绝不出现在任务列表、SSE 或日志中。

### 2. 历史详情

历史项目接口返回 `display_title` 与 `part_number`，前端以“第 N 集 · 标题”显示；来源标识仅作为技术信息保留。历史卡片增加“查看交付详情”，仅在本地会话验证后的接口中请求保存目录，并提供“打开文件夹”。

### 3. 可恢复状态机

系列控制器恢复时检查实际执行器是否存活，而不是仅相信持久化的 `running`。无执行器时必须调用启动器。执行器因可恢复错误退出时，运行时状态记录为 `paused`，并保留面向用户的阻塞原因。恢复操作将启动一个无窗口子进程，从当前检查点继续；不会重跑已完成的集数。

### 4. 错误呈现

第 7 集这类知识提取失败在任务页面显示为“已阻塞，可重试”，而不是“运行中”。第 8 集维持“等待第 7 集完成”。

## 验收标准

- 当运行状态为 `running` 但执行器不存在时，恢复操作确实启动一次执行器。
- 旧系列的项目接口包含可读标题和集数；历史页不再以来源 ID 作为主标题。
- 对具有可用交付目录的旧系列，私有详情接口返回目录；公开任务列表和 SSE 不返回目录。
- 第 7 集失败时任务状态可解释、可恢复，第 8 集不会被误标为已完成。
