# Dashboard 统一工作台视觉设计

## 目标

将 Distill-Everything Dashboard 的任务作战台、新建任务、平台与登录、任务历史和产物库统一为“本地内容蒸馏工作台”。界面以用户确认的深色青蓝参考图为视觉基准，让用户能在一个稳定、清晰且本地优先的界面中发起、理解、跟踪和交付蒸馏任务。

## 设计原则

- 保留现有哈希路由、接口、字段名称与业务动作，不以视觉改版改变下载、登录、暂停、恢复、重试或打开本地目录的行为。
- 使用现有 Fluent UI React v9 组件和现有图标包，不引入第二套组件系统。
- 中文优先。技术编号仅作为辅助信息，不能取代视频标题、任务名称、保存位置和完成时间。
- 本地优先与隐私说明必须可见，但不得显示 Cookie、二维码数据、访问令牌或任何非必要的个人数据。
- 深色界面使用单一青蓝强调色；成功为绿色、等待为中性灰、警告为琥珀色、失败为红色。所有状态均同时有文字，不依赖颜色。
- 支持键盘导航、明显的焦点样式、`prefers-reduced-motion`，并在窄屏改为顶部可横向滚动导航。

## 信息架构

保留五个现有页面与 URL：

| 路由 | 导航名称 | 页面职责 |
| --- | --- | --- |
| `#mission` | 工作台 | 当前任务总览、任务进度、队列、暂停/恢复和实时日志 |
| `#create` | 创建任务 | 来源预检、交付形式、模板预览、保存位置和创建动作 |
| `#platforms` | 平台与登录 | 平台可用性、登录状态和本地扫码入口 |
| `#history` | 任务管理 | 按状态筛选、查看任务、打开保存目录、重试失败作品 |
| `#artifacts` | 知识库 | 选择任务、浏览产物、文本预览、复制和打开文件位置 |

导航从仅文字的左侧栏改为含图标的工作台导航。顶部全局栏展示产品名称、工作台描述、主题、使用指南和设置入口；本轮只渲染已经具备真实目的地的入口，避免出现不可用操作。

## 通用页面骨架

1. 顶部全局栏：品牌 `DISTILL // EVERYTHING`、分隔线与“本地内容蒸馏工作台”。
2. 左侧栏：五个带 Fluent 图标的固定导航项；底部“运行状态”卡显示服务、模型与存储状态，状态来自现有可用数据或明确显示“未检测”。
3. 主内容区：最大宽度、统一 12px 圆角、细边框和低对比面板层次。页面标题使用 28–40px，内容标题使用 20–24px。
4. 右侧上下文区：桌面端在工作台和创建任务页显示任务创建入口或本地优先说明；窄屏移至主内容区末尾。
5. 页脚：显示“开源、本地优先、隐私保护”以及项目地址、文档和问题反馈入口。链接仅指向已有公开地址；无地址时不渲染链接。

## 页面设计

### 工作台

- 顶部“任务概览”卡：圆环总体进度、当前任务标题、当前阶段、线性进度与完成/进行中/等待/总任务数量。
- 右侧“创建任务”卡：仅承载“新建任务”链接和简短说明，不以文件拖放伪装当前 URL 创建流程。
- 队列采用响应式表格。列为序号、作品标题、状态、进度、阶段、更新时间、操作。窄屏时单项卡片保留标题、状态、进度和主操作。
- 当前活动任务和历史完成任务都显示作品标题、BV 号或来源编号、完成或更新时间。技术诊断信息只在“查看详情”抽屉中出现。
- 保留现有暂停、恢复、取消、重试、产物入口和实时日志；其位置移至任务摘要或作品行操作区。

### 创建任务

- 将来源、平台、输出选择、保存位置和操作按钮分组为清晰的步骤区，但不做多步骤向导，避免改变当前预检后创建的流程。
- 输出卡片保留 Markdown、Skill、RAG 分块以及“查看模板”；每张卡解释产物用途和默认保存行为。
- 默认保存位置必须可读；覆盖位置使用当前受控输入和令牌流程，不把原始本地绝对路径写入公开静态内容。
- 预检结果展示创作者、可处理数量、登录状态和下一步；创建成功后提供进入工作台的主按钮。

### 平台与登录

- 平台改为状态卡：平台图标、能力标签、登录状态、简短说明和主操作。
- Bilibili 扫码保留站内模态框、自动轮询、成功后自动关闭并刷新状态。
- 外部浏览器为平台适配器明确要求时，界面清晰告知其原因；不再承诺所有平台都能站内扫码。

### 任务管理与知识库

- 任务管理使用筛选栏和任务列表，每项展示创作者、任务标题、平台、状态、完成进度、保存位置摘要和最后更新时间。
- 展开的作品清单把标题放在第一行，BV 号与完成时间放在第二行；移除默认可见的“技术信息”。失败项目可见失败原因和重试。
- 知识库明确区分任务交付概览、产物列表与文本预览。保存位置与“打开文件夹”仅在用户主动选择任务后显示。

## 组件边界

新增通用展示组件仅限于：

- `DashboardFrame`：顶部栏、侧栏、运行状态、内容容器与页脚。
- `PageHeader`：页面标题、描述和可选操作。
- `StatusPill`：文字化状态及无障碍标签。
- `ProgressSummary`：总体进度、计数与阶段。
- `QueueTable`：桌面表格与移动端项目卡的同一数据呈现。

业务页面继续拥有 API 调用和状态；通用组件只接收已格式化的展示数据与回调，不直接请求接口。

## 验收标准

- 五个页面具有一致的顶部栏、侧栏、面板、状态、按钮和空状态样式。
- 工作台、任务管理和知识库优先显示人类可读标题；当可用时展示 BV 号/来源编号、保存位置和完成时间。
- 现有 App、页面和关键任务控制测试仍通过；新增组件有最小渲染与导航测试。
- 固定 Node 24 运行 TypeScript 编译、Vitest、Vite 构建、静态 Dashboard 构建与静态一致性检查均通过。
- 不在界面、测试夹具、截图或公开文档中写入真实登录凭据、二维码内容、Cookie、真实用户目录或任务内容。

## 不在本次范围

- 不新增后端接口、不改变系列运行器或子进程模型。
- 不改变扫码平台适配方式；抖音仍遵守其外部持久浏览器约束。
- 不实现主题切换、帮助中心和设置页的真实业务逻辑，仅在有现有安全地址时提供链接。
